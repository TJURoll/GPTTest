# ALM CSP 与 atomtxt 的 LLM corpus

2026-09-11 已完成全量生成与验收，`build_report.json` 的状态为 `complete`。117,403 条对话及 112,485 个结构文件全部通过逐条回读核查，正式 train / val 文件已发布。

## 最终使用哪些文件

- `train.jsonl` 用于训练，`val.jsonl` 用于验证。两项任务已合并到这两个文件，可按顶层 `task` 字段筛选 CSP 或 atomtxt。
- `structures/` 存放独立结构文件。`preview.jsonl` 和 `preview.md` 仅展示其中的 10 条，不是另一套训练数据。
- 不生成新的 `test.jsonl`。原 ALM 评估集保持原样，此前与其关联的记录没有重新加入。

正式文件的实际计数如下。

| 任务 | train | val | 合计 |
| --- | ---: | ---: | ---: |
| CSP | 101,252 | 11,233 | 112,485 |
| atomtxt | 4,446 | 472 | 4,918 |
| 合计 | 105,698 | 11,705 | 117,403 |

只使用 `../mp_jarvis_selected/csp.parquet` 和 `../mp_jarvis_selected/atomtxt.parquet` 中的 MP、JARVIS 记录。一条候选记录只生成一条对话，没有枚举模板组合扩增数据量，也没有改写原始结构或 DFT 数值。

## 如何读取结构与对话

每行的 `messages` 只有一条 user 和一条 assistant。没有 system，正文中不放结构全文、结构占位符、文件格式名称或冒号。化学式和空间群符号按真实约束保留，不把合法的化学式片段误当格式名称删除。

| 任务 | 模型输入 | 监督输出 |
| --- | --- | --- |
| CSP | user 文字条件 | assistant 文字及 `output_cif_path` 对应结构 |
| atomtxt | user 文字及 `input_cif_path` 对应结构 | assistant 文字及 `output_cif_path` 对应结构 |

- 路径字段位于 JSON 顶层，不在 user / assistant 正文。CSP 没有输入结构，因此没有 `input_cif_path`，不是漏导出。
- `input_cif_path` / `output_cif_path` 为绝对路径；对应的 `input_cif_relative_path` / `output_cif_relative_path` 相对于本目录，便于搬迁。
- `input_geometry_sha256` / `output_geometry_sha256` 是原始四字段结构对象的哈希；`input_cif_sha256` / `output_cif_sha256` 是导出文件字节哈希，两者含义不同。
- `metadata` 保存模板编号、真实性质值、来源定位、计算方法和审核证据。它不是模型输入，尤其不能把答案数值或目标结构当输入拼进去。结构如何编码或拼接，由后续训练流程决定。

结构采用纯几何写法，显式列出全部原子，只写恒等对称操作，不附带真实空间群标签、DFT 性质或原子计算属性。恒等操作不是在宣称材料真实空间群为 P1。
文件按原始结构哈希存放在 `structures/前两位哈希/完整哈希.cif`。同一实际结构被不同任务复用时共用文件；不同晶胞表示不会仅因结构等价而被合并替换。
晶胞整体朝向由标准晶胞参数表示，不保证导出矩阵与原矩阵逐分量相同；核验比较晶胞度量、手性、元素数量和周期坐标配对。没有做晶胞标准化、原胞化或重新弛豫。

## 模板与标签

- CSP 有 2 个条件子组，20 条 query 和 10 条 response。化学式、空间群及可用晶系逐条回填，不增加原记录没有的晶系条件。
- atomtxt 有 19 个约束子组，95 条 query 和 57 条 response，覆盖形成能、带隙、密度、晶胞体积及各自方向。
- 随机种子为 `20260911`。在同一 split、同一任务、同一子组内分别均衡分配 query 和 response；每种角色各模板的使用次数最多相差 1。两种角色独立打乱，不固定一对一组合。
- 同元素集合与同组成、多晶型与一般结构变体分别处理，不能跨子组混用。晶胞体积任务继续保持输入、输出晶胞原子数一致。
- atomtxt 的 DFT 比较只使用各自来源的已审核数值。MP 的 PBE / PBE+U、JARVIS 的 OptB88vdW 方法信息留在元数据，不被冒充为统一方法；MP 带隙编辑对检查 Hubbard 设置一致。
- 密度和晶胞体积从实际导出结构复算。多晶型对子重新检查无缩放和允许均匀缩放两种情况下均不等价；不混入独立 polymorph 子集。

## 划分与复用

两个任务共同按已有 `split_group_id` 分组，固定随机种子选取约 10% 的组用于 val，其余用于 train，然后才分配模板。不能在两项任务内部各自按行随机重切。
共 107,449 个选中划分组，train 96,704 组、val 10,745 组。整组分配意味着记录比例不必恰好为 90% / 10%。
此前记录的 8,101 个跨任务共享结构等价组保留在同一划分；766 个含多条 CSP 记录的等价组也没有进一步删行。本轮保留既有样本权重，没有宣称做了更宽松意义上的近重复去除。
原评估关联隔离仍沿用上一步审计，不代表所有其他科学数据集之间也已经去重。

## 验收与追溯

本次独立验收复读 112,485 个结构文件和 117,403 条对话，复核 1,289 个多晶型配对。最大周期原子位置误差约为 2.43e-14 Å；18 个冻结输入文件未改变，train / val 的划分组和原始几何哈希重叠均为零。

解析器对少量 He、Ne、Ar 结构记录了电负性表缺项警告。这不是几何或本任务标签缺失；电负性未补值、未导出，相关结构的几何核查均通过。逐文件警告保留在结构索引中。

- 先生成并核验 CSP、atomtxt 各 5 条完整预览，再按同一全量计划生成；最终预览逐行确认是正式 train / val 的原样子集，不重新随机抽换。
- 每个结构文件导出后读回一次，独立验收再读取一次，核对字节哈希、原子数、元素与位置对应、晶胞度量及几何性质。
- CSP 的空间群和晶系在导出结构上重新核对，沿用此前 `symprec=0.01 Å`、`angle_tolerance=5°`，不放宽阈值。
- 全部对话逐条核对来源、模板、参数、配对结构、性质变化方向、路径和划分；检查没有漏样本、重复生成或 train / val 共享划分组。
- `build_report.json` 保存输入校验和、模板使用次数、数量、输出校验和和验收结果。`structure_index.jsonl` 是结构文件索引，`split_manifest.jsonl` 是统一分组清单，二者不是额外训练集。
- 处理脚本为 `../build_mp_jarvis_corpus.py`，验收脚本为 `../verify_mp_jarvis_corpus.py`。原始数据、筛选结果及模板文件不改动。

这些核查针对指令、结构和已有答案之间的对应关系及序列化正确性，不是新的 DFT 计算、逐条力/应力收敛认证或物理可实现性保证。
